# SpendWise

SpendWise is a personal budgeting application. It started as a responsive dashboard built with HTML and CSS, then gained JavaScript to process budget data. This week it became fully interactive: users can set a budget, add and delete expenses, filter them by category, and watch the dashboard update instantly.

## Improvements Made This Week

- Replaced the `prompt()` boxes with real HTML forms (set budget, add expense)
- Stored expenses in an **array of objects** instead of separate variables
- Added summary cards for Monthly Budget, Total Spent and Remaining
- Added a feedback message and a progress bar that change with spending
- Category cards are now generated by JavaScript and update automatically
- Added an expense list with delete buttons and a category filter
- Added form validation with clear error messages
- Added a **Clear All** button and a header shortcut button that jumps to the expense form

## How Conditionals Are Used

Conditional statements let the app give feedback based on the user's data.

**Budget feedback** (`getBudgetFeedback`) uses `if / else if / else` to pick a message and a colour level:

| Condition | Result |
|-----------|--------|
| No budget set | Warning: set a budget |
| Spent more than the budget | Danger: "Over budget by ..." |
| 90% or more used | Danger: "Careful! ..." |
| 70% or more used | Warning: "Heads up ..." |
| Nothing spent yet | OK: "No spending yet" |
| Otherwise | OK: "You are on track!" |

```javascript
if (spent > budget) {
  // over budget
} else if (percent >= 90) {
  // careful
} else if (percent >= 70) {
  // heads up
}
```

Conditionals are also used for:

- **Form validation:** empty descriptions and amounts that are not numbers greater than 0 are rejected with an error message
- **Category badges:** "Over limit" (red), 80% or more (orange), or a normal percentage. Savings is treated as a goal instead of a limit
- **Remaining balance:** turns red when it is negative
- **List filter:** `continue` skips expenses that do not match the selected category

## How Arrays Are Used to Store Data

Two arrays hold the application data.

**`categories`** is an array of objects describing each category:

```javascript
const categories = [
  { name: "Food", icon: "🍔", limit: 500 },
  { name: "Transport", icon: "🚌", limit: 200 },
  // ...
];
```

**`expenses`** is an array of expense records:

```javascript
let expenses = [
  { id: 1, description: "Groceries", category: "Food", amount: 310 },
  // ...
];
```

- `push()` adds a new expense
- `filter()` removes an expense by its `id`
- **Loops** (`for`, `for...of`, `forEach`) work through the arrays to calculate totals, build the category cards, fill the dropdowns and display the list

Using arrays means the app can handle any number of expenses without adding new variables.

## How the DOM Is Updated

The page is never edited by hand. JavaScript redraws it from the data. After any change, a single `render()` function runs four smaller functions:

| Function | What it updates |
|----------|-----------------|
| `renderStats()` | Budget, Total Spent and Remaining numbers |
| `renderFeedback()` | Feedback message, colour level and progress bar width |
| `renderCategoryCards()` | The six category cards |
| `renderExpenseList()` | The list of expenses and the "Showing X of Y" count |

DOM techniques used:

- `document.getElementById()` to select elements
- `document.createElement()` and `appendChild()` to build cards and list items
- `textContent` to insert text safely (user input is never inserted as raw HTML)
- `classList.add()` / `classList.remove()` and `className` to change colours
- `element.style.width` to move the progress bar
- `element.hidden` to show or hide the empty-list message

## How User Interactions Are Handled With Events

| User action | Event | What happens |
|-------------|-------|--------------|
| Submit the budget form | `submit` on `#budget-form` | Validates, saves the new budget, calls `render()` |
| Submit the expense form | `submit` on `#expense-form` | Validates, calls `addExpense()`, resets the form |
| Click a delete (✕) button | `click` on `#expense-list` | Calls `deleteExpense(id)` |
| Change the category filter | `change` on `#filter-select` | Updates the filter and redraws the list |
| Click Clear All | `click` on `#clear-btn` | Asks for confirmation, empties the array, calls `render()` |
| Click "+ Add Expense" in the header | `click` on `#header-add-btn` | Scrolls to the form and focuses the first field |

Form handlers call `event.preventDefault()` so the page does not reload. The delete buttons use **event delegation**: one listener on the list handles every button, including ones created later.

**The flow:** user action → event listener → data changes → `render()` → page updates.

## Challenges and How I Solved Them

- **Delete buttons that do not exist yet:** the buttons are created by JavaScript, so adding a listener to each one was a challange. I used event delegation with `event.target.closest(".delete-btn")` and a `data-id` attribute to know which expense to remove it.
- **Keeping the page and data in sync:** at first it was easy for the totals and the list to disagree. I fixed this by keeping all data in the arrays and redrawing everything from them with one `render()` function.
- **Invalid input:** empty fields, zero, or negative numbers could break the calculations. I added validation with `trim()`, `parseFloat()` and `isNaN()`, and show an error message instead.
- **Safe output:** inserting user text with `innerHTML` could allow HTML injection, so I used `textContent` for everything the user types.
- **Git push rejected:** pushing to GitHub failed with "fetch first" because the remote had commits I did not have locally. I fixed it with `git pull --rebase origin main` and then `git push`.

## Layout and Styling

- **CSS Grid** for the page layout, the stats row, the forms and the card grid
- **Flexbox** inside the sidebar, header, cards, forms and list items
- **CSS custom properties** on `:root` for the theme (brand, accent, surface, text, plus success, warning and danger colours)
- **Dark theme** by overriding only the `:root` variables inside `@media (prefers-color-scheme: dark)`
- **Responsive** single-column layout below 768px
- **Card hover and focus animations** of 200ms using `transform` and `box-shadow`
